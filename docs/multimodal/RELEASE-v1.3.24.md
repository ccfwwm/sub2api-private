# Sub2API v1.3.24

渠道检测现在支持监控默认值和逐模型提示词、正常耗时上限及请求超时。文本、图片、视频、音频分别采用 6 / 90 / 300 / 60 秒的默认正常耗时上限；成功但慢的检测仍计入可用率。模板应用、复制和旧数据兼容继承这些设置。

- 修复中文截断经过 JSON 往返超过 500 字节、历史写入失败但最近检测时间仍更新的问题。历史和检测时间在同一事务保存。
- 媒体任务使用稳定样本标识、加密结果回执和原任务恢复；保存失败或进程重启后先补存结果，避免重复提交。异步生成按协议轮询，并保留总耗时和查询耗时。
- 手动检测支持后台执行和 24 小时结果查询。管理员及用户视图区分暂无数据、读取异常、过期结果和真实 0% 可用率。
- 新增加法迁移 256，部署管理器校验固定 SQL，并要求备份、隔离恢复和旧程序兼容演练。
- 准备资源候选预算，保留 Redis 认证与 RDB/AOF 策略，修复空认证健康检查。扩容须通过七天采样、恢复演练和至少 30 分钟的 1.5 倍峰值负载门禁；本应用发布不自动应用资源预算。

当前真实渠道记录为 v1.3.23 上的模型列表连通性核验，历史生成案例仅作基线。新版本的生产切换和一次生成验收另行记录，不把旧结果补成新监控样本。

配置与恢复说明见 [渠道监控修复说明](./CHANNEL_MONITOR_REPAIR_CN.md)。
