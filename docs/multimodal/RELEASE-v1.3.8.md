# Sub2API v1.3.8

修复上游查询返回 HTTP 200、任务正文却为 `failed` 时，本站遗漏错误码和请求编号的问题，并修复任务详情页只展示最初受理响应的问题。

- 模板和兼容适配器均保留失败正文中的 `error.code`、`error.message`、`error.request_id`；响应头中的请求编号优先，正文作为回退来源，全部经过脱敏。
- 管理端分别展示、复制原始提交响应和最新上游任务响应；失败任务自动展开最新响应，因此历史任务已保存的错误编号也能查看。
- 不改变任务计费、并发、状态判定或重试策略，不自动重新提交已受理任务，无新增数据库迁移。

发布前对生产已有的 1 个成功视频和 4 个失败视频进行了本站、上游双向只读查询。失败任务均由上游返回 `internal_error`；本版本修复本站诊断信息丢失，不代表上游生成故障已经恢复。未提交新的付费请求。详见 `CHANNEL_VERIFICATION_CURRENT.json` 和 `INCIDENT-2026-10-29.md`。
