# 媒体输入统一与管理员模板体系计划（v1.2.15 候选修订版）

日期：2026-10-21。本文是实施和发布验收计划，不表示全部模板链路已经实现或版本已经发布。

用户统一提交 `images`、`videos`、`audios`，素材可为公网 HTTPS URL、完整 MIME Data URL 或兼容的 Base64 对象。管理员维护协议模板，并在模型绑定中明确选择模板版本、账号、分组、上游模型和覆盖规则。运行时不根据供应商域名、模型名称或名称前缀猜测协议；通用规则与可编辑模板负责表达上游差异。

## 2. 初始调查发现的问题

以下是实施前确认的问题及设计背景，不代表每一项在当前候选中仍未修复；当前实现和验证状态以本计划后续步骤及最终候选报告为准。

1. `backend/internal/media/capability.go` 按旧 `v6k_url` 名称拒绝编码素材，导致请求未到上游就失败。基础候选修复已去掉该限制，保留媒体探测、大小和网络边界。
2. `backend/internal/media/adapter.go` 的 `FieldMapping` 仅在 legacy 模式生效，显式云飞/V6K 跳过，无法完成动态覆盖。
3. `Material.ReferenceField` 只接受有限平面别名，无法表达 Grok 的 `image.url` 和数组转单对象。
4. 账号已有 `extra.media_models` 与 `credentials.model_mapping` 协调机制，不能增加第三套互相覆盖的模型真源。分组部分精确映射属于 Messages 调度，不能直接当作媒体映射。
5. 版本化配置表已有草稿/发布/历史；`media_config_versions.kind` 的 CHECK 仅允许 capability/price，新增规则需要正式迁移、类型和后端接口，不能只在前端塞 JSON。
6. 界面“云飞 Base64”“V6K 公网 URL”混淆协议、编码和模型能力，需要同步更名及修正公开能力说明。

## 3. 公共输入合同

```json
{
  "model": "公开模型名称",
  "prompt": "根据素材生成视频",
  "seconds": 5,
  "ratio": "16:9",
  "images": ["https://example.com/logo.png"],
  "videos": ["data:video/mp4;base64,<FULL_VIDEO_BASE64>"],
  "audios": ["data:audio/mpeg;base64,<FULL_AUDIO_BASE64>"]
}
```

只提供实际拥有的素材。字符串、`{"url":"..."}`、`{"b64_json":"..."}` 统一解析，保留顺序、`role`、`weight` 和扩展属性。推荐完整 MIME Data URL；裸 Base64 需要真实 MIME 检测、解码与大小校验。

兼容旧 `reference_*`、URL 别名、`duration/aspect_ratio`。同语义值一致可归一，不一致明确报错；严格区分缺失、null、false、0、空字符串和空数组。

独立、无草稿的 API 请求可以省略素材进行文生视频。创作项目已保存的非空素材意图不得被省略字段或空数组静默抹除，清除使用明确操作并形成新草稿版本。

公开能力、SDK 示例及创作工具默认展示规范字段。既有 Gemini/Ark 原生结构保留，不强行改成通用视频协议。

## 4. 作用域、模型映射与执行顺序

入口：截图中的“图片音频视频分组” → 编辑 → “媒体模型适配”；账号模型编辑页提供同一规则的跳转和供应商配置入口。

作用域按真实鉴权分组、操作、公开模型精确匹配，可进一步限定账号。调用方不能伪造分组或账号。第一版支持分组默认与精确模型，不引入难以判断重叠的正则模型匹配。

执行顺序：

1. 解析公开模型身份、实际分组、原始请求和素材意图，检查别名冲突。
2. 合并协议预设、账号模型配置、分组已发布规则，执行规范字段上的语义覆盖。
3. 测量素材；按有效时长、分辨率、输出数量等确定价格与预留，按既有调度选取合格账号。
4. 经现有模型解析得到上游模型；该分组精确模型可显式覆盖其映射值。账号成本、供应商规则一起冻结。
5. 编译发送规则、生成最终 HTTP 请求，检查素材无丢失且计费语义不变，记录实际发送摘要。

优先级：协议预设 < 账号模型配置 < 分组默认 < 分组精确模型 < 分组精确模型 + 账号限定。每个候选账号分别解析配置与价格，最终只冻结选中组合。操作按稳定规则 ID 合并/显式替换，不把各层改名串行执行。同级重复命中或争写相同路径时发布失败。

模型只进行一次公开模型 → 上游模型解析，不递归映射。详情保存 requested/effective/upstream model；禁止用通用 `set.model` 改写计费身份。现有 `NormalizeMediaAccountConfig` 继续协调旧账号映射，分组映射是作用域覆盖，不复制第二份账号真源。

## 5. 动态规则与计费一致性

使用有类型、可预览的声明规则，不执行脚本。路径采用受限 JSON Pointer，支持嵌套对象和明确数组投影，不允许任意表达式、网络访问或读取凭据。

| 操作 | 行为 | 合同 |
| --- | --- | --- |
| default | 仅缺失时补值 | 不把 0、false、null、[] 视为缺失 |
| set | 固定标量、数组或对象 | 影响费用的值提前在语义阶段执行并展示覆盖 |
| rename/move | 改 key 或移动至嵌套路径 | 目标不同值、循环、父子覆盖及重复目标报错 |
| map | 如 wide → landscape | 未匹配默认拒绝；配置 `on_unmapped: "preserve"` 显式选择原值透传，默认值为 `error` |
| shape | 字符串/对象包装、数组逐项转换、单项数组转对象 | 数量不符合要求就拒绝，禁止暗取首项 |
| add | 添加供应商常量或允许的规范字段引用 | 不允许引用密钥、用户身份或账务变量 |
| drop/allowlist | 删除指定可选参数或启用白名单 | 未配置时未知参数透传；删除进入预览与审计 |

语义阶段处理时长、分辨率、数量、生成音频开关等可能影响费用的字段。发送阶段只改变表示，例如 seconds → duration、数字 → 明确要求的字符串、images → reference_images。影响费用的固定值或值映射必须提前应用，重新计算有效请求与价格。

估价与提交共用规则编译器和请求构造器。旧估价对应的规则版本变化时明确失效/重新估价，不能按旧价发新请求。发送规则不能改变已用于报价的模型、时长、数量和素材集合。

非空素材、prompt、模型身份、幂等和账务字段受保护。过滤不能把带素材任务变为纯文本。素材可选属性默认保留，显式过滤必须展示差异，承担语义的 role 不得静默消失。供应商不支持时保留素材并报错。

保留身份和模型权限、价格配置、大小、Base64 解码限制、SSRF 及真实 MIME/时长测量。过时目录的素材类型/数量和可选参数只用于提示，缺项不能直接判为不支持。“数组转单图必须恰好一项”是结构转换要求，不通过截断绕过。

## 6. 管理员模板库

模板按请求与响应格式命名，不按供应商、域名或模型名称选择。管理员可以编辑内置模板并产生新版本，也可以复制、新建、导入和导出；绑定明确指定模板版本。下面列出首批模板，供应商名只可作为管理员自己的适用说明：

| 模板 | 默认结构与用途 |
| --- | --- |
| 通用视频·复数素材数组 | `images`/`videos`/`audios`、`seconds`/`ratio` |
| 通用视频·reference 数组 | `reference_images`/`reference_videos`/`reference_audios`、`duration`/`aspect_ratio` |
| 单图视频·URL 对象 | 单个素材映射为 `image: {url: ...}`；多图拒绝，不取第一张 |
| 视频·首尾帧角色数组 | 图片数组保留 `first_frame`/`last_frame` 角色 |
| 视频·独立首尾帧字段 | 将首帧、尾帧分别映射到管理员指定字段 |
| 多媒体·类型内容块 | 按配置的 `text`、`image`、`video`、`audio` 内容块提交 |
| 图片生成·JSON | 同步 JSON 与 URL/`b64_json` 结果 |
| 图片编辑·JSON 参考数组 | 多张参考图及可选蒙版 |
| 图片编辑·multipart | 文件字段、重复字段和蒙版上传 |
| Gemini parts·图片/音频输出 | 可配置 `contents/parts/inlineData` 与结果解析 |
| 音乐生成·Chat JSON | `messages` 输入、音频链接或编码结果 |
| 音频生成·异步任务 | 提交、查询及音频制品下载 |
| 语音合成·二进制响应 | 文本、声音、格式参数和音频文件响应 |
| 自定义空白模板 | 管理员从头配置请求、查询与结果链路 |

素材编码和对象形态在模板内分别选择：保留 URL、Data URL 或裸 Base64；字符串、`url`/`b64_json` 对象或内容块。Grok 的单图模板保持独立但可编辑；不把 `{data,mime_type}` 固定为任何上游的默认格式。模板配置认证引用账号安全存储，不保存密钥。

模型绑定示意（实际字段由版本化 schema 校验）：

```json
{
  "id": "group-66-public-video-model",
  "status": "enabled",
  "group_id": 66,
  "model": "公开模型名称",
  "account_id": 123,
  "upstream_model": "管理员填写的上游模型 ID",
  "template": {"id": "video-reference-arrays", "version": 2},
  "rules": [
    {"phase": "semantic", "op": "default", "target": "seconds", "value": 8},
    {"phase": "wire", "op": "rename", "source": "images", "target": "reference_images"}
  ]
}
```

模型绑定可指定分组默认、分组精确公开模型及分组精确模型+账号覆盖，按固定优先级合并。管理员填写模型映射；代码不依据名字推断。数组转单图必须恰好有一项；素材角色或属性无法表达时明确报错。默认值只补字段缺失，不覆盖用户明确提交的秒数。

## 7. 界面、配置版本与迁移

界面包含协议模板库、模型绑定、继承来源、模型发现和认证引用。模板编辑器有基本信息、发现、提交、素材、响应、查询、下载、预览、测试、发布、历史与回滚；表单和 JSON 双模式共用 schema，切换模式不能丢高级字段。绑定页展示公开模型、上游模型、账号、分组、模板版本和覆盖来源，不自动启用发现到的模型，也不自动改价格。

免费预览显示：规范输入、语义覆盖差异、有效请求与估价、实际上游模型、最终发送体、素材数量/顺序/角色、过滤清单与规则版本。Base64 只显示 MIME、大小与摘要，预览不得创建付费任务。真实测试是独立操作，明确模型、素材、秒数和费用信息。

复用 media_config_heads/media_config_versions 的草稿、发布、乐观锁、历史与审计，增加 `template`、`binding` 配置类型和校验器。公开请求不能改配置。后端管理员接口统一位于 `/api/v1/admin/media/`，检查管理员权限并审计变更；发布原子激活并失效缓存。模板正文、绑定、上游模型和实际发送体仅管理员可读；公共任务保留用户自己的状态、费用、脱敏错误和规范素材摘要。

现有账号、分组、价格与映射无损读取。旧模板引用只根据已保存且可确认的协议字段迁移，不根据域名或模型名称猜测；不能等价映射的旧能力保留配置、禁用并标记“待配置协议模板”。已有管理员绑定优先保留。迁移必须可重复执行，冲突展示而不静默覆盖。

任务冻结规则 ID/版本/hash、账号与映射结果、有效请求、素材摘要和最终请求 hash。旧任务轮询、重启恢复、结算和幂等重放使用原快照，更新不改变在途任务。回滚发布历史版本的新指针，不覆盖历史字节。数据库追加兼容迁移，旧应用回退保留扩展数据，不自动删表。

## 8. 创作插件与详情

AI Cloud 向中转只提交规范素材字段，不在插件维护另一套分组转换配置。保留 references_file、JSON 和参数入口的冲突检查、非空素材意图、失败草稿、任务 ID、明确清空、重启恢复和账号隔离。

详情分别展示原始请求、有效请求、准备发送、已尝试发送、上游已受理与最终完成，附规则版本、删改差异、素材摘要、实际字段与 request hash。历史缺少发送快照就显示“未记录”。错误区分本地归一/规则冲突、网关拒绝、上游拒绝和提交状态不确定，透传脱敏错误码、说明与 request ID。

超时/状态不确定时保留原任务和证据，不自动重新 POST。音频真实输入与 multipart 文件上传继续按现有合同验证，本次不以视频用例宣称全面覆盖。
