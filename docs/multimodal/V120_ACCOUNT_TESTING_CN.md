# v1.2.0 账号模型与测试

媒体账号使用一个模型表维护模型名称、上游映射、类型、启用状态和测试记录。已知模型自动使用协议预设；未知模型必须选择接口类型。同步仅返回候选模型，不自动启用、覆盖高级参数或修改渠道定价。

保存和启用不要求实测通过。测试结果只是状态记录，既不会自动启用模型，也不会生成价格。业务请求继续使用现有渠道／分组定价和参数校验。

`extra.media_models` 是媒体能力的权威配置，保存时同时更新标准 `credentials.model_mapping`。旧客户端单账号映射更新会保留已有模型的高级覆盖。媒体批量映射更新必须同时提供能力表，以免覆盖各账号的不同配置。既有映射冲突按实际能力路由解释，并在编辑界面提示。云飞的旧 Omni／Veo 空占位配置自动采用预设，保留启用状态和自定义覆盖。

两处测试入口共用一个弹窗，支持连接检查、最小生成和自定义生成。提示词可编辑、可恢复默认；媒体的自定义参数经过业务参数校验。关闭模型及未配置售价的模型可以进行管理员测试，管理员测试不扣用户余额，上游生成仍可能收费。

连接检查以真实凭证请求 `/v1/models`，只证明上游认证和模型发现接口连通，**不证明生成接口、异步任务或产物通过**。无独立模型发现接口的认证协议会明确提示使用最小生成。模拟测试单独标识。

最小生成只提交一个请求、一个产物。图片选择配置中最小有效像素尺寸；Omni 选择 4 秒、Veo 固定预设为 8 秒；音频默认短纯音乐。生成成功必须取得并校验有效产物，仅任务提交成功不会记录为通过。失败或提交状态不确定时不会自动重复收费请求。

测试记录保存在现有数据目录的 `account-tests`（可通过 `SUB2API_ACCOUNT_TEST_DATA_DIR` 覆盖），使用稳定 JWT Secret 加密。最新摘要写回账号 Extra，不新增数据库迁移。应用启动只恢复已经受理任务的查询／下载；提交中断且没有任务 ID 时标记不确定，不重发。关闭弹窗后可重新查看，修改凭证或能力后会显示旧配置结果。

增量接口：

- `POST /api/v1/admin/accounts/:id/test` 保留 SSE、`model_id`、`prompt`、`mode`，新增可选 `test_kind=connection|minimal|custom`、`operation`、`parameters`。各平台原有 `mode` 含义保留。
- `GET /api/v1/admin/accounts/:id/tests/:test_id` 获取持久结果；`test_id=latest` 获取账号最近结果。
- `GET /api/v1/admin/accounts/:id/tests/:test_id/artifacts/:key` 获取产物。两个查询接口均要求管理员认证，产物按账号归属校验。

本轮真实验证按用户最终要求只做接口连通检查，每个适配协议选择一个代表，停止价格调查和昂贵生成。实测范围与结果见 `CHANNEL_VERIFICATION_CURRENT.json`；生成行为、单次提交、失败、异步恢复和产物校验由隔离的自动化测试验证，不能据此宣称真实渠道生成通过。

# 正式版本自动部署

普通提交、候选镜像和预发布版本不会切换生产。Private Release 成功完成源码测试、镜像启动检查和部署演练，并发布正式 Release 后，调用同一个生产部署工作流；补发正式 Release 也复用此入口。

部署使用专用受限 SSH Key，固定主机公钥，只允许 `deploy vMAJOR.MINOR.PATCH` 和 `status JOB_ID`。宿主机读取正式 Release 清单，校验源码、校验和、真实验证记录和固定 digest 的镜像身份，通过 `/root/sub2api-manage` 完成真实备份和隔离恢复演练后，仅替换应用容器。

本轮按用户授权直接切换，不等待请求排空。连接可能中断，应用短暂不可用。PostgreSQL、Redis、定价服务和生产数据保留，切换前后核对容器身份。迁移校验、互斥锁、应用回滚和内外网健康检查继续生效。重复部署同一版本只复核健康与镜像，旧版本不能覆盖较新版本。GitHub 持续查询宿主机持久任务，最终上线核验通过才报告成功。
