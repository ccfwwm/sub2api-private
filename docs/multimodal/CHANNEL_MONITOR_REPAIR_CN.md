# 渠道监控修复与容量切换

监控和请求模板增加 `probe_config`，默认值位于 `defaults`，逐模型覆盖位于 `models[模型名]`。支持 `prompt`、`normal_latency_ms`、`request_timeout_ms`、`observation_timeout_ms`。前端以秒输入，API 以毫秒保存；空配置保持兼容。

| 检测类型 | 正常耗时上限 | 单次请求超时 |
|---|---:|---:|
| 文本 | 6 秒 | 45 秒 |
| 图片 | 90 秒 | 180 秒 |
| 视频 | 300 秒 | 180 秒 |
| 音频 | 60 秒 | 180 秒 |

请求超时范围为 1～600 秒。同步协议正常耗时上限必须小于请求超时，异步协议必须小于总观察期限（默认 3600 秒）。协议模板最终解析后再次校验。统一提示词优先于媒体默认提示词；完整替换请求和自定义 HTTP 请求的内容由请求体编辑器控制。文本未自定义时保留算术校验。

异步手动执行：`POST /api/v1/admin/channel-monitors/:id/run?async=true` 返回 `run_id`；`GET /api/v1/admin/channel-monitors/:id/runs/:run_id` 查询状态和结果，有效期 24 小时。原同步入口兼容保留。定时和手动执行共用互斥锁，活动任务不重复生成。

任务受理前保存加密日志。已完成结果先写加密回执，再将历史与 `last_checked_at` 事务保存，提交成功后确认回执。进程重启或数据库临时故障只重放保存；媒体终态以任务标识去重。观察超时保留原任务查询能力。旧的受理未知任务必须先核对原任务及结算证据，然后通过现有重置接口恢复，不能直接删除或重新收费。

可用率为正常或降级终态样本数除以全部终态样本数，排除生成中记录。无样本显示暂无数据，查询失败显示读取异常；过期结果标记旧数据，并展示实际结果时间和样本数。历史缺口不以业务成功记录填充。

生产扩容候选值位于 `deploy/capacity.rakserver.env.example`，尚须七天完整采样、隔离恢复和至少 30 分钟的 1.5 倍峰值负载验证。应用 8 GiB、PostgreSQL 16 GiB、Redis 2 GiB 为待验证预算；全局 work_mem 保持 4 MiB，媒体 worker 保持现有 150。保留 Redis noeviction、RDB 原计划及 AOF 关闭状态，宿主机 CPU 和内存均保留至少 20% 余量。

应用修复通过正式 Release 和现有管理器发布；迁移 256 必须在备份副本演练中确认新旧程序兼容、旧业务数据不变。资源覆盖须在门禁通过后叠加到现有管理体系的 active.json 之后，并排空流量后切换。PostgreSQL 和 Redis 资源切换会短暂断连。失败仅回退程序或参数，保留最新业务数据。
