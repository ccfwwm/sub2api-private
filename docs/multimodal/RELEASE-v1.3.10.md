# Sub2API v1.3.10

修复生产升级备份在媒体目录持续产生新文件时失败的问题。此前备份对活动目录递归遍历，目录在归档过程中变化会让 GNU tar 中止；该失败发生在应用切换之前，生产仍运行原版本。

- 备份前生成固定的 NUL 分隔文件清单，再由 GNU tar 按清单逐项归档，避免递归扫描被新任务改变的目录。
- 滚动日志继续排除；清单中原有文件缺失或在归档时变化仍会失败，不会生成不完整备份并继续部署。
- 在生产主机 GNU tar 1.35 上使用临时目录验证：48 个清单媒体文件完整归档，并发新增的 150 个文件及滚动日志均未进入归档。
- 应用代码、数据库结构、媒体并发和计费行为与 v1.3.9 相同。v1.3.9 的上游失败响应诊断修复随版本保留；没有自动重提任务或提交新的付费生成。

生产现有任务的只读核验记录见 `CHANNEL_VERIFICATION_CURRENT.json` 和 `INCIDENT-2026-10-29.md`。任务 `mt_658d944b-a422-482d-afe8-51c678c6eb8c` 已完成；截图中的其他失败由第三方上游返回 `internal_error`。本站会保留并展示错误码和请求编号，供应商内部故障仍需供应商按请求编号排查。
