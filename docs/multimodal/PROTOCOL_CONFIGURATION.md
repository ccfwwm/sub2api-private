# 媒体协议模板配置

模板负责把统一媒体请求转换为上游接口格式；账号模型固定引用模板版本。定价仍按公开模型名从渠道定价匹配。

## 素材字段映射

统一输入使用 `images`、`videos`、`audios`。每条素材规则指定输入类型、上游目标字段、编码和每项结构：

- 上游要求 `images: ["https://..."]`：结构选择“字符串 URL / 数据”。
- 上游要求 `images: [{"url":"https://..."}]`：结构选择“包含 url 的对象”。
- 上游接受附带角色或扩展属性的对象：选择“保留对象结构”。
- 上游用 `reference_images`：修改目标字段，不修改用户素材。

当上游不接受普通参考图的角色属性时，精确过滤 `{"role":["reference"]}`。只有字段和值都相同时才移除。它不会移除 `first_frame`、`last_frame` 或未配置的扩展属性。字符串结构仍有其他属性无法表示时会拒绝请求，避免静默丢失素材意图。

内置 `v6k-video-reference-string` 为 `/v1/videos` 的普通图片参考提供此转换；它不根据模型名称推测协议，也不会自动改动现有账号绑定。先免费预览，再明确选择账号模型绑定。历史任务继续使用其创建时的完整快照。

## 响应解析

在“任务响应解析”中分别填写任务 ID、状态、进度、错误、成品 URL 和 Base64 路径，每行一个候选路径。`data.id` 表示嵌套对象；`data[].url` 表示数组中的每个 URL。上游状态通过表格转换，例如 `queued → in_progress`、`succeeded → completed`、`failed → failed`。

只有上游直接返回编码成品时才填写 Base64 路径。异步任务填写查询接口，`{task_id}` 使用提交返回的真实 ID；上游只提供成品内容端点时填写内容接口。复杂 `results`、用量和 PCM 转换继续使用完整响应 JSON；编辑常用字段会保留这些高级配置。

用免费预览粘贴真实提交与查询响应，核对任务 ID、状态和成品解析。预览不会提交生成，素材在线测量也不会创建生成任务。

## 管理员请求与响应

任务详情按用户入站、归一化参数、模板准备请求、实际上游请求、上游提交响应分区展示。新提交回执记录方法、路径、编码、请求体、文件数据、HTTP 状态和内容类型。媒体正文和签名素材 URL 对管理员保留，便于复制复测；账号密钥、密码和服务器文件路径仍被保护。普通用户不会获得管理员证据。

旧任务回执只能展示当时保存的内容；旧版本已省略的 Base64 不能还原。未记录实际提交时明确显示“未记录”，不把计划请求冒充已提交证据。超时或受理状态不明时先按原任务核查，不自动重新生成。
